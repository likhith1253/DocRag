## 2. Bugs Found & Root Cause Analysis

### Bug 1: Unconditional Divergence in Routing Logic (`agents/orchestrator.py`)
- **Root Cause**: In `route_node`, when `repo_id` was omitted from the incoming HTTP request payload, `rank_repositories` returned multiple candidate repositories (`len(top_repos) > 1`). The ambiguity detection block returned early with an informational string without setting `updates["repo_id"]`. LangGraph hard-wired execution to `retrieve_node`, which saw `repo_id = None`, fell back to the default empty `"chunks"` collection, found 0 chunks, and caused `agent_node` to return `"I cannot find this information in the uploaded documents."`.
- **File Modified**: [agents/orchestrator.py](file:///d:/DocRag/agents/orchestrator.py)
- **Fix**: Updated `route_node` to automatically set `updates["repo_id"] = top_repos[0]` whenever `top_repos` returns candidate collections.

#### Code Change (Bug 1):

### Bug 2: Router Collection Description Truncation (`retrieval/repository_router.py`)
- **Root Cause**: `_build_collection_description` was truncating paper titles to the first 5 alphabetically sorted titles (`[:5]`). Because `Modelling_Human_Routines_Conceptualising_Social_Pr.pdf` started with 'M', it was sorted past index 5 and omitted from the routing embedding. This caused `rank_repositories` to calculate low similarity for routing queries targeting that paper.
- **File Modified**: [retrieval/repository_router.py](file:///d:/DocRag/retrieval/repository_router.py)
- **Fix**: Removed `[:5]` paper titles truncation so all indexed papers in a collection are included in the routing embedding.

### Bug 3: String Multiplication Precedence Bug in Prompt Builder (`agents/doc_agent.py`)
- **Root Cause**: In `_build_grounding_prompt`, string literal implicit concatenation inside parenthesized expressions combined with `"═" * 80` caused Python operator precedence to multiply the entire 12,000-character prompt header and context block by 80. This resulted in a **1,224,315 character (~249,327 token)** prompt, exceeding context limits and stalling PyTorch CPU attention.
- **File Modified**: [agents/doc_agent.py](file:///d:/DocRag/agents/doc_agent.py)
- **Fix**: Defined an explicit separator variable `sep = "=" * 80` and used explicit `+` string concatenation. This reduced prompt size from **1,224,315 characters down to 15,615 characters (~3,148 tokens)**, restoring execution.
